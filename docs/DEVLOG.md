# 개발 기록

결정과 그 이유, 실패한 시도를 남깁니다. 새 작업을 할 때마다 맨 아래에 날짜와 함께 추가하세요.

## v0.1 — 첫 MVP

- 창원시 30일 시뮬레이션으로 효과 크기를 먼저 확인: 반품 1건 물류비 −16.4%. 보수적 가정에서도 −9.9%라 구현할 가치가 있다고 판단.
- 매칭을 반품별로 가장 가까운 주문에 보내는 방식 대신 최소비용 흐름(Min Cost Flow)으로 정식화. 반품끼리 같은 주문을 두고 경쟁할 때 전체 비용을 줄이기 위함.
- 처리 경로 6개(직송, 거점 보관, 판매자 반송, 리퍼, 기부, 폐기)를 기대가치 식으로 비교.

## v0.2 — 발표 신뢰도 개선

| 문제 (발견 경로) | 원인 | 바꾼 것 |
|---|---|---|
| 확률이 95%에서 더 오르지 않음 | Isotonic 보정이 계단형 | Platt 보정(연속)으로 교체 |
| 얼룩진 사진이 점수를 올림 | 윤곽선 개수를 품질로 봄 | 선명도·밝기·대비 기반 "사진 품질 점수"로 재정의. 결함 판독은 하지 않는다고 명시 |
| 흰 배경 사진이 감점됨 | 밝기 식이 너무 밝은 사진을 과하게 감점 | 밝기 식 수정 |
| "왜 이 값인가" 설명 불가 | 점수만 표시 | 기여도: 기준값 + 입력별 %p = 최종값 (테스트로 합 검증) |
| 사유는 "사이즈", 메모는 "얼룩" | 텍스트를 따로 보지 않음 | 불일치 시 경고, 직송 차단 |
| 반례 절감액이 76원뿐 | 반례 시나리오가 약함 | 가까운 순서 배정이 판매자 반송을 유발하는 시나리오로 재설계 (28,595원 → 6,794원) |
| 파손 사유인데 선명한 사진이 +20%p | 사진 품질이 결함 여부와 무관 | 불량·파손 사유일 때 사진 기여도를 0 이하로 제한 (실행 점검 중 발견) |
